# Keitaro Flow

Локальное веб-приложение для создания и управления кампаниями Keitaro. Интерфейс позволяет просматривать кампании и потоки, управлять офферами и долями трафика. Backend обращается к Keitaro Admin API; frontend не хранит API-ключ.

> Изменения кампаний и потоков отправляются в подключённый Keitaro. Перед работой с рабочим аккаунтом проверьте настройки и выберите нужный аккаунт.

## Возможности

- Поиск кампаний Keitaro по названию или ID.
- Создание кампании с гео-потоком и стартовым оффером.
- Просмотр потоков, фильтров и статистики за сегодня: клики, уникальные клики и боты.
- Добавление офферов в редактируемый поток, изменение их активности и долей.
- Закрепление доли оффера, чтобы автоматическое перераспределение её не меняло.
- Локальное хранение записей о кампаниях, офферах и изменениях в SQLite.

## Как устроено приложение

```text
Браузер (React + Vite)
        │ запросы /api; в dev-среде проксируются на localhost:8000
        ▼
FastAPI ───────────────► Keitaro Admin API
   │                     кампании, потоки, офферы, статистика
   ▼
SQLAlchemy ────────────► SQLite (локальные записи и журнал изменений)
```

- **React 19** отображает интерфейс; **Vite** запускает dev-сервер и проксирует `/api` на backend.
- **FastAPI** предоставляет HTTP API приложения.
- **SQLAlchemy 2** описывает модели и подключает локальную базу.
- **Keitaro Admin API** — источник актуальных кампаний, потоков, офферов и статистики.
- По умолчанию используется SQLite. Для разработки и обычного локального запуска отдельный сервер базы данных не нужен.

## Требования

- Python 3.10 или новее.
- Node.js 20.19 или новее; рекомендуется Node.js 22 LTS.
- Доступ к Keitaro Admin API и API-ключ для загрузки данных и изменения кампаний.

## Установка и первый запуск

Все команды backend выполняйте **из корневой папки проекта** — той, где находятся `README.md`, `backend/` и `frontend/`.

### 1. Установить backend и создать `.env`

macOS / Linux:

```bash
cd ~/Desktop/keitaro-wrapper-fastapi
python3 -m venv .venv
./.venv/bin/python -m pip install -r backend/requirements.txt
if [ ! -f .env ]; then cp .env.example .env; fi
```

Откройте `.env` в корне проекта и заполните параметры подключения из раздела [Настройки](#настройки). Команда не перезаписывает существующий `.env`. Не вставляйте API-ключ в исходный код и не отправляйте его в чаты.

При желании активируйте виртуальное окружение:

```bash
source .venv/bin/activate
```

Активация необязательна: команды ниже вызывают Python и Uvicorn напрямую из `.venv`, поэтому не зависят от того, какое виртуальное окружение было активировано ранее.

### 2. Запустить backend

В первом терминале, из корня проекта:

```bash
cd ~/Desktop/keitaro-wrapper-fastapi
./.venv/bin/python -m uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

Оставьте терминал открытым. Успешный запуск отмечается строкой `Application startup complete`.

### 3. Запустить frontend

Во втором терминале:

```bash
cd ~/Desktop/keitaro-wrapper-fastapi/frontend
npm install
npm run dev -- --host 127.0.0.1
```

`npm install` нужен при первой установке или после изменения `frontend/package.json`; при обычном запуске достаточно `npm run dev`. Оставьте этот терминал открытым.

### 4. Открыть приложение

- Интерфейс: http://localhost:5173
- Интерактивная документация FastAPI: http://localhost:8000/docs
- Проверка доступности backend: http://localhost:8000/api/health

Для остановки каждого сервера нажмите `Ctrl+C` в соответствующем терминале. Если порт занят, сначала найдите уже запущенный сервер и остановите его; не запускайте второй экземпляр на том же порту.

### Windows (PowerShell)

Из корневой папки проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Заполните `.env`, затем в первом окне PowerShell запустите backend:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

В отдельном окне PowerShell запустите frontend:

```powershell
Set-Location frontend
npm install
npm run dev -- --host 127.0.0.1
```

## Настройки

Пример полного файла находится в [`.env.example`](./.env.example). Приложение читает `.env` из **корня проекта**, не из `backend/`.

| Переменная | Назначение |
| --- | --- |
| `KEITARO_BASE_URL` | Базовый адрес вашей установки Keitaro, например `https://keitaro.example.com`. Не добавляйте `/admin_api/v1`; завершающий `/admin` код умеет убрать. Если схема не указана, приложение добавляет `https://`. |
| `KEITARO_API_KEY` | API-ключ с разрешениями, необходимыми для просмотра и изменения кампаний. |
| `KEITARO_TIMEOUT` | Таймаут запросов к Keitaro в секундах; по умолчанию `20`. |
| `DATABASE_URL` | Строка подключения SQLAlchemy. По умолчанию `sqlite:///./data/keitaro_wrapper.db`. |
| `DEFAULT_GROUP_NAME` | Название группы кампаний Keitaro, по умолчанию `FORTESTS`. Для создания кампании название должно соответствовать существующей группе. |
| `DEFAULT_SOURCE_NAME` | Название источника трафика, по умолчанию `FORTESTS`. Для создания кампании должно соответствовать существующему источнику. |
| `DEFAULT_DOMAIN` | Домен трекинга. Если оставить пустым и Keitaro возвращает ровно один домен, он выбирается автоматически; если доменов несколько, задайте нужный. |
| `GOOGLE_URL` | URL назначения для гео-потока; по умолчанию `https://www.google.com`. |
| `PORT` | Присутствует в примере конфигурации, но текущая команда запуска задаёт порт параметром Uvicorn `--port 8000`. При смене порта обновите также адрес proxy в `frontend/vite.config.js`. |

`DEFAULT_GROUP_NAME` и `DEFAULT_SOURCE_NAME` сравниваются с названиями из Keitaro. Если в вашем аккаунте используются другие названия, укажите их в `.env`. При нескольких доменах укажите доменное имя в `DEFAULT_DOMAIN`.

После изменения `.env` перезапустите backend: значения загружаются при старте приложения.

### PostgreSQL (необязательно)

Для локального запуска рекомендуется оставить SQLite. Если нужен PostgreSQL, установите драйвер и задайте `DATABASE_URL` в `.env`:

```bash
./.venv/bin/python -m pip install "psycopg[binary]"
```

```env
DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/keitaro_wrapper
```

Убедитесь, что сервер PostgreSQL запущен, база создана, а имя пользователя и пароль корректны. Драйвер PostgreSQL не входит в [список базовых зависимостей backend](./backend/requirements.txt).

## Сценарии работы

### Просмотр кампаний

После загрузки интерфейс запрашивает у Keitaro список кампаний. Найдите кампанию по названию или ID и выберите её. ID последней выбранной кампании сохраняется в `localStorage` браузера.

В карточке кампании отображаются её потоки, фильтры, состояние и статистика за текущий день. Потоки со схемой офферов можно редактировать; прочие потоки показываются только для чтения.

### Создание кампании

1. Откройте **«Новая кампания»**.
2. Введите название, гео-коды из двух букв (например, `AU, MX`) и выберите стартовый оффер из Keitaro.
3. Нажмите **«Создать кампанию»**.

Приложение нормализует гео-коды в верхний регистр и убирает повторы. Название создаётся с префиксом `test_` и суффиксом `_campaign`. Затем backend создаёт кампанию и два потока: гео-поток с фильтром стран и переходом на `GOOGLE_URL`, а также поток со стартовым оффером и долей 100%.

Домен, группа и источник берутся из значений по умолчанию в `.env`; в форме они показаны только для просмотра. Если создание потоков не удаётся, backend пытается удалить уже созданную кампанию.

### Редактирование офферов и распределение трафика

Изменения сначала появляются как черновик в интерфейсе. Можно:

- добавить существующий в Keitaro оффер в поток;
- активировать или деактивировать оффер;
- изменить долю активного незакреплённого оффера;
- закрепить текущую долю или снять закрепление;
- сбросить несохранённый черновик либо применить его.

Перед сохранением сумма долей **активных офферов** должна быть равна 100%. Закреплённые доли сохраняются, а оставшаяся часть распределяется между незакреплёнными офферами. Нельзя отключить последний активный оффер. Для применения изменений нажмите **«Применить изменения»**; до этого момента черновик не отправляется в Keitaro.

Если оффер больше не найден в Keitaro, он отображается неактивным и его нельзя включить, пока оффер не восстановлен на стороне Keitaro.

## API

Полная интерактивная документация доступна по адресу http://localhost:8000/docs.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | Проверка, что backend запущен. Не проверяет доступность Keitaro. |
| `GET /api/meta` | Домены, группы, источники и выбранные значения по умолчанию из Keitaro. |
| `GET /api/offers?q=&limit=` | Поиск офферов; `limit` ограничивается диапазоном 1–100. |
| `GET /api/campaigns?q=` | Список кампаний с необязательным поисковым запросом. |
| `POST /api/campaigns` | Создание кампании и её потоков. |
| `GET /api/campaigns/{campaign_id}` | Данные кампании, потоки, офферы и статистика за сегодня. |
| `PUT /api/campaigns/{campaign_id}/streams/{stream_id}/offers` | Применение изменений офферов потока. |
| `GET /api/debug/stream/{stream_id}` | Получение потока из Keitaro для диагностики. Не публикуйте этот endpoint наружу без необходимости. |

Ошибки API возвращаются в JSON с полем `detail`. В частности, `503` означает, что не заданы обязательные настройки подключения, а `502` — что запрос к Keitaro завершился ошибкой.

## База данных

По умолчанию SQLAlchemy использует SQLite-файл `data/keitaro_wrapper.db`. Папка `data/` создаётся автоматически. Запускайте backend из корня проекта: относительный путь к файлу базы отсчитывается от текущей рабочей папки.

В локальной базе хранятся:

- `campaign_records` — записи о кампаниях, созданных приложением;
- `campaign_offers` — локальное состояние офферов и долей для синхронизации;
- `offer_changes` — журнал изменений офферов.

База приложения **не является копией базы Keitaro**: актуальные кампании, офферы, потоки и статистика запрашиваются через Keitaro Admin API. Таблицы создаются при запуске по SQLAlchemy-моделям; отдельные миграции Alembic в проекте пока не настроены.

## Тесты и production-сборка

Команды выполняйте из корня проекта.

Backend-тесты:

```bash
./.venv/bin/python -m pytest -q backend/tests
```

Frontend-тесты (Node.js test runner):

```bash
cd frontend
node --test src/*.test.js
```

Production-сборка frontend:

```bash
cd frontend
npm run build
```

Результат сборки появится в `frontend/dist/`. Для production разместите статические файлы на подходящем сервере и настройте reverse proxy `/api` на FastAPI. Dev-сервер Vite не предназначен для production. Для production также настройте CORS и сетевой доступ в соответствии с инфраструктурой; не открывайте API-ключ браузеру.

## Диагностика

| Сообщение | Что проверить |
| --- | --- |
| `Could not open requirements file ... backend/requirements.txt` | Вы находитесь не в корне проекта. Выполните `cd ~/Desktop/keitaro-wrapper-fastapi`, затем установку backend. |
| `zsh: command not found: uvicorn` | Активировано не то окружение или вы находитесь не в корне проекта. Используйте `./.venv/bin/python -m uvicorn ...` из корня. |
| `Address already in use` | На порту 8000 уже работает backend. Не запускайте второй экземпляр; остановите первый через `Ctrl+C` в его терминале. |
| Ошибка Vite proxy `ECONNREFUSED` | Backend не запущен или слушает другой порт. Проверьте http://localhost:8000/api/health и настройку proxy в `frontend/vite.config.js`. |
| `503` и сообщение о `KEITARO_BASE_URL` / `KEITARO_API_KEY` | Проверьте, что обе переменные заданы в `.env` в корне проекта, затем перезапустите backend. |
| `502` от API | Backend доступен, но Keitaro вернул ошибку или не ответил. Проверьте адрес Keitaro, доступность сети, API-ключ и его права. Не публикуйте ключ вместе с логами. |
| Не удаётся создать кампанию: не настроены домен, группа или источник | Укажите в `.env` существующие `DEFAULT_DOMAIN`, `DEFAULT_GROUP_NAME` и `DEFAULT_SOURCE_NAME`. Для домена также возможен автоматический выбор, если Keitaro возвращает ровно один домен. |

## Структура проекта

```text
backend/
  app/
    main.py       FastAPI-приложение и HTTP-маршруты
    config.py     загрузка настроек из корневого .env
    database.py   SQLAlchemy engine и сессии
    models.py     модели локальной базы
    keitaro.py    клиент Keitaro Admin API
    service.py    бизнес-логика кампаний и офферов
  tests/          тесты backend
  requirements.txt
frontend/
  src/
    App.jsx       интерфейс и пользовательские сценарии
    formatters.js форматирование фильтров Keitaro
  vite.config.js  dev-сервер и proxy /api
  package.json
.env.example      пример локальных настроек
```

## Безопасность

- Храните реальные значения только в локальном `.env`; не коммитьте и не публикуйте его.
- API-ключ используется backend для запросов к Keitaro и не передаётся frontend.
- Запускайте локальный dev-сервер на `127.0.0.1`, если доступ из локальной сети не требуется.
- Создание кампании и изменение долей выполняют реальные операции в Keitaro.
