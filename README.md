# Keitaro Flow

Keitaro Flow — веб-приложение для создания рекламных кампаний Keitaro и управления потоками офферов. Приложение взаимодействует с Keitaro через Admin API, а локальные данные о кампаниях, офферах и изменениях хранит в SQLite.

**Основной стек:** Python, FastAPI, SQLAlchemy, React 19, Vite, SQLite.

## История разработки и альтернативная реализация

Первоначально проект был разработан на стеке MERN (MongoDB, Express, React, Node.js) с использованием Vite.

После изучения технического задания было принято решение дополнительно реализовать приложение на FastAPI и SQLAlchemy, поскольку эти технологии указаны в требованиях к backend и работе с базой данных.

В результате были созданы две самостоятельные реализации одного проекта:

**Текущая реализация — FastAPI + React**

- Backend: Python и FastAPI.
- Работа с базой данных: SQLAlchemy 2.
- Локальная база данных: SQLite.
- Frontend: React 19 и Vite.
- Взаимодействие с рекламным трекером через Keitaro Admin API.

**Первоначальная реализация — MERN + Vite**

- Backend: Node.js и Express.
- Работа с базой данных: MongoDB и Mongoose.
- Frontend: React и Vite.
- Взаимодействие с рекламным трекером через Keitaro Admin API.

Первоначальная реализация сохранена в отдельном репозитории:

**[Keitaro Flow — первоначальная версия (MERN + Vite)](https://github.com/bakytdeveloper/keitaro-wrapper)**

Обе версии являются самостоятельными реализациями с разными технологическими стеками. Текущий репозиторий содержит версию, подготовленную в соответствии с требованиями технического задания.

## Реализованный функционал

- Поиск кампаний Keitaro по названию или ID.
- Создание кампании с гео-потоком на заданный URL и потоком выбранного стартового оффера.
- Автоматическое формирование названия кампании по схеме `test_<введённое значение>_campaign`.
- Просмотр потоков, фильтров и статистики кампании за текущий день: кликов, уникальных кликов и ботов.
- Добавление существующих в Keitaro офферов в редактируемый поток.
- Включение и деактивация офферов без удаления локальной записи. Неактивные офферы отображаются с долей `0%`.
- Изменение процентных долей офферов и закрепление доли, чтобы автоматическое перераспределение её не меняло.
- Подготовка изменений в черновике: изменённые значения отображаются в интерфейсе до применения.
- Применение изменений или сброс черновика к последнему загруженному состоянию.
- Сохранение выбранной кампании между перезагрузками страницы.
- Локальное хранение записей о кампаниях, офферах и журнале изменений в SQLite.
- Получение актуальных кампаний, потоков, офферов и статистики непосредственно из Keitaro Admin API.

## Как устроено приложение

```text
Браузер (React + Vite)
       │ запросы /api; в dev-среде проксируются на localhost:8000
       ▼
FastAPI ───────────────► Keitaro Admin API
   │                        кампании, потоки, офферы, статистика
   ▼
SQLAlchemy ────────────► SQLite
                            локальные записи и журнал изменений
```

- **React 19** отвечает за пользовательский интерфейс.
- **Vite** запускает frontend в режиме разработки и проксирует запросы `/api` на backend.
- **FastAPI** предоставляет HTTP API приложения.
- **SQLAlchemy 2** описывает модели и подключение к локальной базе данных.
- **Keitaro Admin API** является источником актуальных данных о кампаниях, потоках, офферах и статистике.
- По умолчанию используется SQLite. Для локальной разработки отдельный сервер базы данных не требуется.

## Требования

- Python версии `3.10` или новее.
- Node.js версии `20.19` или новее; рекомендуется Node.js `22 LTS`.
- Доступ к Keitaro Admin API с разрешениями, необходимыми для просмотра и изменения кампаний.
- API-ключ Keitaro.

## Установка и запуск

Все команды backend выполняйте из корневой папки проекта — той, где находятся `README.md`, `backend/` и `frontend/`.

### 1. Подготовьте backend и файл `.env`

macOS / Linux:

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -r backend/requirements.txt
if [ ! -f .env ]; then cp .env.example .env; fi
```

Если `.env` уже существует, не перезаписывайте его: проверьте и измените необходимые значения в существующем файле.

Откройте `.env` в корне проекта и укажите параметры своего окружения из раздела [Настройки](#настройки). Не вставляйте API-ключ в исходный код и не публикуйте файл `.env`.

При желании активируйте виртуальное окружение:

```bash
source .venv/bin/activate
```

Активация необязательна: команды ниже используют Python и Uvicorn непосредственно из `.venv`.

### 2. Запустите backend

В первом терминале, из корневой папки проекта:

```bash
./.venv/bin/python -m uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

Оставьте терминал открытым. Успешный запуск отмечается строкой `Application startup complete`.

### 3. Установите зависимости и запустите frontend

Во втором терминале:

```bash
cd frontend
npm install
npm run dev -- --host 127.0.0.1
```

`npm install` требуется при первой установке или после изменения `frontend/package.json`. При обычном запуске достаточно команды `npm run dev`.

### 4. Откройте приложение

- Веб-интерфейс: http://localhost:5173
- Документация FastAPI: http://localhost:8000/docs
- Проверка доступности backend: http://localhost:8000/api/health

Для остановки каждого сервера нажмите `Ctrl+C` в соответствующем терминале. Если порт занят, сначала найдите и остановите уже запущенный сервер, а не запускайте второй экземпляр на том же порту.

### Windows (PowerShell)

Выполните команды из корневой папки проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Заполните `.env`, затем в первом окне PowerShell запустите backend:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

В отдельном окне PowerShell запустите frontend:

```powershell
Set-Location frontend
npm install
npm run dev -- --host 127.0.0.1
```

## Настройки

Пример конфигурации находится в [`.env.example`](./.env.example). Приложение читает `.env` из **корневой папки проекта**, а не из `backend/`.

| Переменная | Назначение | Пример / значение по умолчанию |
|---|---|---|
| `KEITARO_BASE_URL` | Базовый адрес установки Keitaro. Не добавляйте `/admin_api/v1`; завершающий `/admin` приложение умеет убрать. Если схема не указана, добавляется `https://`. | `https://keitaro.example.com` |
| `KEITARO_API_KEY` | API-ключ с разрешениями, необходимыми для просмотра и изменения кампаний. | Создаётся в Keitaro |
| `KEITARO_TIMEOUT` | Таймаут запросов к Keitaro в секундах. | `20` |
| `DATABASE_URL` | Строка подключения SQLAlchemy. | `sqlite:///./data/keitaro_wrapper.db` |
| `DEFAULT_GROUP_NAME` | Название существующей группы кампаний Keitaro. | `FORTESTS` |
| `DEFAULT_SOURCE_NAME` | Название существующего источника трафика Keitaro. | `FORTESTS` |
| `DEFAULT_DOMAIN` | Домен трекинга. Если оставить пустым и Keitaro возвращает ровно один домен, он выбирается автоматически. | Например, `track.example.com` |
| `GOOGLE_URL` | URL назначения для гео-потока. | `https://www.google.com` |
| `PORT` | Присутствует в примере конфигурации. Текущая команда запуска задаёт порт через параметр Uvicorn `--port 8000`. | `8000` |

`DEFAULT_GROUP_NAME` и `DEFAULT_SOURCE_NAME` должны совпадать с названиями, существующими в Keitaro. Если в аккаунте используются другие значения, укажите их в `.env`. Если доменов несколько, задайте нужный домен в `DEFAULT_DOMAIN`.

После изменения `.env` перезапустите backend: настройки загружаются при запуске приложения.

### PostgreSQL (необязательно)

Для обычного локального запуска рекомендуется оставить SQLite. Если требуется PostgreSQL, установите драйвер:

```bash
./.venv/bin/python -m pip install "psycopg[binary]"
```

Затем укажите строку подключения в `.env`:

```env
DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/keitaro_wrapper
```

Перед запуском убедитесь, что сервер PostgreSQL доступен, база данных создана, а имя пользователя и пароль указаны верно. Драйвер PostgreSQL не входит в базовый список зависимостей `backend/requirements.txt`.

## Создание кампании

1. Откройте раздел **«Новая кампания»**.
2. Введите название кампании.
3. Укажите гео-коды стран из двух букв, разделённые запятыми, например `AU, MX`.
4. Найдите и выберите стартовый оффер из Keitaro.
5. Нажмите **«Создать кампанию»**.

Название кампании автоматически формируется с префиксом `test_` и суффиксом `_campaign`. Гео-коды нормализуются: приложение приводит их к верхнему регистру и удаляет повторения.

После создания кампании backend создаёт два потока:

- гео-поток с фильтром выбранных стран и переходом на URL из `GOOGLE_URL`;
- поток со стартовым оффером и долей `100%`.

Домен, группа и источник берутся из значений по умолчанию в `.env`; в форме они отображаются только для просмотра. Если создание потоков завершается ошибкой, backend пытается удалить уже созданную кампанию.

## Работа с долями офферов

1. Выберите кампанию и поток, который поддерживает редактирование офферов.
2. Добавьте существующий в Keitaro оффер либо измените активность, закрепление или долю оффера.
3. Проверьте черновые значения в интерфейсе.
4. Нажмите **«Применить изменения»**, чтобы отправить корректировки в Keitaro, или сбросьте черновик, чтобы вернуться к последнему загруженному состоянию.

Перед применением сумма долей **активных офферов** должна составлять `100%`. Закреплённые доли сохраняются, а оставшаяся часть распределяется между активными незакреплёнными офферами. Неактивный оффер имеет долю `0%`. Нельзя отключить последний активный оффер.

Изменения не отправляются в Keitaro до нажатия **«Применить изменения»**. Если оффер больше не найден в Keitaro, он отображается неактивным и его нельзя включить, пока оффер не будет восстановлен на стороне Keitaro.

## Где получить API-ключ Keitaro

Войдите в административную панель Keitaro, откройте **Профиль → API-ключи**, создайте ключ для приложения и сохраните его в `KEITARO_API_KEY` в файле `.env`.

Не передавайте API-ключ в клиентский код, не публикуйте его и не добавляйте `.env` в Git. Запросы к Keitaro выполняет backend.

## API приложения

Полная интерактивная документация доступна по адресу http://localhost:8000/docs.

| Метод | URL | Назначение |
|---|---|---|
| `GET` | `/api/health` | Проверка, что backend запущен. Не проверяет доступность Keitaro. |
| `GET` | `/api/meta` | Получение доменов, групп, источников и значений по умолчанию из Keitaro. |
| `GET` | `/api/offers?q=&limit=` | Поиск офферов. Параметр `limit` ограничивается диапазоном от 1 до 100. |
| `GET` | `/api/campaigns?q=` | Получение списка кампаний с необязательным поисковым запросом. |
| `POST` | `/api/campaigns` | Создание кампании и её потоков. |
| `GET` | `/api/campaigns/{campaign_id}` | Получение данных кампании, потоков, офферов и статистики за сегодня. |
| `PUT` | `/api/campaigns/{campaign_id}/streams/{stream_id}/offers` | Применение изменений офферов потока. |
| `GET` | `/api/debug/stream/{stream_id}` | Получение потока из Keitaro для диагностики. Не публикуйте endpoint наружу без необходимости. |

Ошибки API возвращаются в JSON с полем `detail`:

- `503` — не заданы обязательные настройки подключения.
- `502` — запрос к Keitaro завершился ошибкой.

## База данных

По умолчанию SQLAlchemy использует SQLite-файл `data/keitaro_wrapper.db`. Папка `data/` создаётся автоматически. Запускайте backend из корневой папки проекта: относительный путь к файлу базы отсчитывается от текущей рабочей директории.

В локальной базе хранятся:

- `campaign_records` — записи о кампаниях, созданных приложением;
- `campaign_offers` — локальное состояние офферов и долей для синхронизации;
- `offer_changes` — журнал изменений офферов.

База приложения **не является копией базы Keitaro**. Актуальные кампании, офферы, потоки и статистика запрашиваются через Keitaro Admin API. Таблицы создаются при запуске на основе SQLAlchemy-моделей; отдельные миграции Alembic в проекте пока не настроены.

## Проверки и production-сборка

Команды backend выполняйте из корневой папки проекта.

### Backend-тесты

```bash
./.venv/bin/python -m pytest -q backend/tests
```

### Frontend-тесты

```bash
cd frontend
node --test src/*.test.js
```

### Production-сборка frontend

```bash
cd frontend
npm run build
```

Результат сборки появится в `frontend/dist/`. Для production разместите статические файлы на подходящем сервере и настройте reverse proxy `/api` на FastAPI. Dev-сервер Vite не предназначен для production.

Для production также настройте CORS и сетевой доступ в соответствии с инфраструктурой. Не открывайте API-ключ браузеру.

## Диагностика

| Проблема | Что проверить |
|---|---|
| `Could not open requirements file ... backend/requirements.txt` | Команда выполняется не из корня проекта. Перейдите в папку, где находятся `README.md` и `backend/`. |
| `zsh: command not found: uvicorn` | Используйте `./.venv/bin/python -m uvicorn ...` из корня проекта. |
| `Address already in use` | На порту 8000 уже работает backend. Остановите предыдущий процесс через `Ctrl+C`, прежде чем запускать новый. |
| Ошибка Vite proxy `ECONNREFUSED` | Backend не запущен или использует другой порт. Проверьте `http://localhost:8000/api/health` и proxy в `frontend/vite.config.js`. |
| `503` и сообщение о `KEITARO_BASE_URL` / `KEITARO_API_KEY` | Проверьте обе переменные в `.env` в корне проекта и перезапустите backend. |
| `502` от API | Проверьте адрес Keitaro, доступность сети, API-ключ и его права. Не публикуйте ключ вместе с логами. |
| Не удаётся создать кампанию из-за домена, группы или источника | Укажите в `.env` существующие `DEFAULT_DOMAIN`, `DEFAULT_GROUP_NAME` и `DEFAULT_SOURCE_NAME`. Если Keitaro возвращает ровно один домен, он может быть выбран автоматически. |
